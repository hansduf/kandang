SKENARIO DETAIL:

Nama: Login
Actor: Pekerja Kandang / Pemilik Peternakan
Tujuan: Masuk ke sistem untuk akses fitur sesuai role

PRECONDITION:
• Sistem menampilkan halaman login
• User belum authenticated

FLOW UTAMA:
1. User buka aplikasi → halaman login tampil
2. User input username → system terima input
3. User input password → system terima input
4. User klik "Login" → system validasi di database
5. System check: username & password valid?
   - VALID: lanjut ke step 6
   - TIDAK: tampilkan error "Username/Password salah" → kembali ke step 2
6. System query user dari database → ambil role
7. System set session/token untuk user
8. System redirect ke dashboard sesuai role:
   - Role "pekerja" → Pekerja Dashboard
   - Role "pemilik" → Pemilik Dashboard

POSTCONDITION:
• User sudah authenticated
• Session/token tersimpan
• User akses dashboard sesuai role

ERROR HANDLING:
A1. Username/Password Salah
    → Error message: "Username/Password salah"
    → Allow retry (max 5 attempts)

A2. Akun Terkunci (5+ failed attempts)
    → Error message: "Akun terkunci. Hubungi administrator"
    → Log activity untuk security

A3. Database Error
    → Error message: "Server error. Coba lagi nanti"
    → Log error untuk debugging

DETAIL PROSES:

Nama: Input Produksi Telur Harian
Actor: Pekerja Kandang
Tujuan: Mencatat hasil produksi telur harian kandang mereka

PRECONDITION:
• Pekerja sudah login
• Pekerja memiliki kandang yang terdaftar di sistem
• Halaman input produksi sudah terbuka

MAIN FLOW:
Step  Action By        System Response
─────────────────────────────────────────────────────────────
1.    Pekerja klik     Tampilkan form input produksi
      "Input Produksi"

2.    -                Pre-fill kandang_id (dari session)
                       Set read-only (pekerja tidak bisa ubah)

3.    Pekerja pilih    Terima input tanggal
      tanggal produksi

4.    Pekerja pilih    Terima pilihan satuan (butir/kg)
      satuan (butir/kg)

5.    Pekerja input    Terima input angka
      jumlah

6.    Pekerja input    Terima input text (optional)
      keterangan

7.    Pekerja klik     Validasi:
      "Simpan"         • Tanggal ≤ hari ini?
                       • Jumlah > 0?
                       • Kandang valid?
                       
8.    -                IF valid → lanjut step 9
                       IF tidak → tampilkan error

9.    -                Konversi satuan:
                       IF satuan_input = 'butir'
                         jumlah_butir = input
                         jumlah_kg = input / 16
                       ELSE
                         jumlah_kg = input  
                         jumlah_butir = input * 16

10.   -                INSERT produksi_telur ke database
                       Catat: kandang_id, user_id, 
                       tanggal, satuan, jumlah,
                       jumlah_butir, jumlah_kg, keterangan

11.   -                UPDATE stok_telur:
                       stok_butir += jumlah_butir
                       stok_kg = stok_butir / 16
                       updated_at = NOW()

12.   -                Tampilkan success message
                       Redirect ke halaman riwayat produksi

POSTCONDITION:
• Data produksi tersimpan di database
• Stok telur otomatis bertambah
• Pekerja melihat riwayat produksi terbaru

ERROR & EXCEPTION:
E1. Tanggal lebih besar dari hari ini:
    Message: "Tanggal tidak boleh di masa depan"
    Action: Pekerja pilih ulang tanggal

E2. Jumlah 0 atau negatif:
    Message: "Jumlah harus lebih dari 0"
    Action: Pekerja input angka yang valid

E3. Kandang tidak valid (security check):
    Message: "Kandang tidak ditemukan"
    Action: Log security, contact admin

E4. Database error:
    Message: "Gagal menyimpan data. Coba lagi"
    Action: Retry atau contact admin

DETAIL AKSI EDIT/DELETE:

EDIT:
1. Pemilik klik "Edit" pada row tertentu
2. Sistem buka form dengan data terpopulasi
3. Pemilik ubah data (jumlah, satuan, tanggal)
4. Sistem re-konversi satuan
5. Sistem hitung delta stok (old - new)
6. Sistem update stok dengan delta tsb
7. Sistem update record produksi
8. Success message, reload tabel

DELETE:
1. Pemilik klik "Delete" pada row
2. Sistem tampilkan konfirmasi "Apakah Anda yakin?"
3. Jika confirm:
   - Sistem hitung stok yang akan dikurangi
   - Sistem update stok_telur (decrement)
   - Sistem delete record dari produksi_telur
   - Sistem tampilkan success
4. Tabel reload
