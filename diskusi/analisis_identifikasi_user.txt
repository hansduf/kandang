ANALISIS IDENTIFIKASI USER SISTEM
==================================

Berdasarkan dokumentasi sistem dan konteks bisnis Hans Jaya Poultry Farm, berikut analisis LENGKAP tentang identifikasi user:

═══════════════════════════════════════════════════════════════════════════════
1. USER/ACTOR YANG TERLIBAT
═══════════════════════════════════════════════════════════════════════════════

A. PEKERJA KANDANG (Farm Worker)
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ IDENTITAS                                                               │
   ├─────────────────────────────────────────────────────────────────────────┤
   │ • Nama              : Pekerja/Pengelola Kandang (Farm Handler)           │
   │ • Jumlah            : 1 - N (tergantung jumlah kandang & shift)          │
   │ • Lokasi utama      : Di lapangan/lokasi kandang                        │
   │ • Hubungan dengan   : Pemilik peternakan (atasan langsung)             │
   │   sistem            :                                                   │
   └─────────────────────────────────────────────────────────────────────────┘

   DESKRIPSI DETIL:
   Pekerja kandang adalah tenaga kerja operasional yang bekerja langsung 
   merawat, memberi makan, mati-matian ayam, dan melakukan pengawasan harian 
   di lokasi kandang. Mereka bertanggung jawab untuk:
   
   1. Observasi/Monitoring harian
      - Mengamati ayam setiap hari
      - Mencatat dampak produksi (kesehatan ayam, kondisi kandang, dll)
   
   2. Pencatatan Produksi Telur
      - Mengumpulkan/menghitung telur yang diproduksi per hari
      - Menimbang atau menghitung dalam satuan butir
      - Mencatat data produksi ke sistem
   
   3. Pelaporan ke atasan (Pemilik)
      - Menyampaikan informasi kondisi kandang
      - Melaporkan masalah/kendala

   KONTEKS BISNIS:
   • Biasanya bekerja shift pagi, siang, atau malam tergantung kebijakan
   • Mungkin ada 1-2 pekerja per kandang
   • Umumnya memiliki pendidikan dasar-menengah
   • Bekerja berdasarkan upah harian atau bulanan


B. PEMILIK PETERNAKAN (Farm Owner / Manager)
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ IDENTITAS                                                               │
   ├─────────────────────────────────────────────────────────────────────────┤
   │ • Nama              : Pemilik/Pengelola Usaha Hans Jaya Poultry Farm   │
   │ • Jumlah            : 1 (bisa juga Multiple if ada co-owner)            │
   │ • Lokasi utama      : Kantor/rumah + lapangan (mobile)                  │
   │ • Hubungan dengan   : Owner dari usaha (decision maker)                │
   │   sistem            :                                                   │
   └─────────────────────────────────────────────────────────────────────────┘

   DESKRIPSI DETIL:
   Pemilik peternakan adalah pengambil keputusan utama yang mengelola aspek 
   bisnis dan operasional peternakan. Bertanggung jawab untuk:
   
   1. Perencanaan & Pengelolaan Bisnis
      - Menentukan strategi produksi
      - Memantau kinerja kandang
      - Analisis profitabilitas
   
   2. Pengelolaan Master Data
      - Menambah/mengubah/menghapus kandang
      - Menentukan/mengubah harga telur (berdasarkan pasar)
      - Mengelola data pengguna/pekerja
   
   3. Pencatatan Transaksi Penjualan
      - Mencatat setiap transaksi penjualan
      - Menentukan jumlah, satuan, dan harga
      - Validasi stok sebelum menjual
   
   4. Analisis & Laporan
      - Melihat laporan produksi per kandang
      - Melihat laporan penjualan & revenue
      - Membuat keputusan berdasarkan data
   
   5. Monitoring Real-time
      - Melihat stok telur terkini
      - Memonitor produksi dari berbagai kandang
      - Alert jika ada masalah

   KONTEKS BISNIS:
   • Umumnya berpendidikan minimal SMA, banyak yang sarjana
   • Sudah familiar dengan teknologi/komputer
   • Membutuhkan dashboard dan laporan yang detail
   • Akses dibutuhkan kapan saja (mobile-friendly)

4. DATA SCOPE PER USER ROLE
═══════════════════════════════════════════════════════════════════════════════

A. PEKERJA KANDANG

   Data yang bisa diakses:
   ✓ Dashboard kandang sendiri
   ✓ Riwayat produksi kandang sendiri
   ✓ Lihat informasi kandang yang ditugaskan
   ✓ Lihat stok telur (informatif)

   Data yang TIDAK bisa diakses:
   ✗ Kandang lain (bukan tanggung jawabnya)
   ✗ Data penjualan
   ✗ Data harga telur detail (hanya lihat saat input)
   ✗ Data pengguna lain
   ✗ Pengaturan sistem
   ✗ Laporan finansial

   Implementasi:
   - Query WHERE user_id = logged_in_user AND kandang_id IN (assigned_kandangs)
   - Middleware untuk filter data per role
   - Scope di Model Eloquent untuk auto-filter


B. PEMILIK PETERNAKAN

   Data yang bisa diakses:
   ✓ SEMUA candang (unlimited)
   ✓ SEMUA data produksi
   ✓ SEMUA data penjualan
   ✓ SEMUA harga telur (historis)
   ✓ SEMUA laporan & analytics
   ✓ Data pengguna/pekerja
   ✓ Pengaturan sistem
   ✓ Dashboard keseluruhan

   Data yang tidak bisa diakses:
   ✗ Password pengguna lain (hash only)
   ✗ Log sistem/audit trail (opsional)

   Implementasi:
   - Minimal scope/WHERE clause
   - Full dashboard access
   - Admin-level permissions

6. TECHNICAL IMPLEMENTATION NOTES
═══════════════════════════════════════════════════════════════════════════════

Database Relations:
• users table → role (enum: 'pekerja', 'pemilik')
• users table → kandang_id (nullable, pekerja assigned to 1+ kandang)
• produksi_telur → user_id (who input), kandang_id
• penjualan → user_id (who recorded), multiple items per transaksi
• harga_telur → berlaku_dari (historis, never deleted)
• kandang → user_id (optional, for track who manage?), aktif (boolean)

Laravel Implementation:
1. Authentication
   - Use Spatie/Laravel Permission package
   - Define 2 roles: 'pekerja', 'pemilik'

2. Authorization (Middleware/Policy)
   - Middleware untuk role-based redirect (route groups)
   - Policy untuk resource authorization
   - Scope Query untuk auto-filter data per role

3. Model Relationships
   - User hasMany ProduksiTelur, Kandang, Penjualan
   - User belongsToMany Kandang (pivot with role info)
   - Kandang hasMany ProduksiTelur, Penjualan
   - Scopes: ->forUser(auth()->user())

4. Frontend
   - Blade conditional (@can directive) untuk show/hide menu
   - Form validation per role
   - Dashboard templates per role

7. PERTANYAAN UNTUK DISKUSI
═══════════════════════════════════════════════════════════════════════════════

1. Apakah ada kemungkinan satu Pekerja ditugaskan ke MULTIPLE kandang?
   → Mempengaruhi scope filter data

2. Apakah ada Supervisor/Team Lead di atas Pekerja?
   → Jika ya, perlu role ke-3

3. Apakah ada sistem Approval untuk Penjualan?
   → Misal Pekerja input, Pemilik approve?

4. Apakah Pekerja bisa edit produksi yang sudah diinput?
   → Sekarang assume: TIDAK, hanya Pemilik

5. Berapa jumlah Pekerja & Kandang aktif saat ini?
   → Untuk estimasi load/performance

6. Apakah ada Customer/Supplier Management?
   → Atau simple input saja tanpa merchant record?

7. Apakah perlu Audit Log/Activity Log?
   → Untuk track siapa mengubah apa & kapan
