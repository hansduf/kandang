SKENARIO 1: LOGIN
================================================================================

┌─────────────────────────────────────────────────────────┐
│              Skenario Login Sistem                      │
└─────────────────────────────────────────────────────────┘

| Nama          | Login                                         |
|---------------|-----------------------------------------------|
| Actor         | Pekerja Kandang / Pemilik Peternakan         |
| Tujuan        | Masuk ke sistem dengan kredensial yang valid |
| Kondisi Awal  | Sistem menampilkan halaman login             |
| Kondisi Akhir | Sistem menampilkan dashboard sesuai role     |

SKENARIO UTAMA (Basic Flow)

| # | Actor                          | Sistem                                    |
|---|--------------------------------|-------------------------------------------|
| 1 | User membuka aplikasi          | Sistem menampilkan halaman login          |
| 2 | User memasukkan username       | Sistem menerima input username            |
| 3 | User memasukkan password       | Sistem menerima input password            |
| 4 | User klik tombol "Login"       | Sistem validasi kredensial di database    |
| 5 |                                | Sistem memverifikasi role pengguna        |
|   |                                | (pemilik / pekerja)                       |
| 6 |                                | Sistem set session/token user             |
| 7 |                                | Sistem redirect ke dashboard sesuai role  |
| 8 |                                | Pekerja: Dashboard Pekerja Kandang        |
|   |                                | Pemilik: Dashboard Pemilik Peternakan     |

SKENARIO ALTERNATIF (Error Cases)

A1. Username atau Password Salah
    • Step 4: Sistem deteksi kredensial invalid
    • Sistem tampilkan error: "Username/Password salah"
    • Pengguna dapat retry login (Max 5 attempts)

A2. Akun Terkunci (5+ failed login attempts)
    • Sistem deteksi multiple failed attempts
    • Sistem lock akun selama 30 menit
    • Tampilkan pesan: "Akun terkunci. Hubungi administrator"
    • Log security event untuk audit trail

A3. Database Connection Error
    • Sistem tidak dapat terhubung ke database
    • Tampilkan error: "Server error. Coba lagi nanti"
    • Log error untuk debugging

SKENARIO 2: INPUT PRODUKSI TELUR HARIAN
================================================================================

┌─────────────────────────────────────────────────────────┐
│       Skenario Input Produksi Telur Harian             │
└─────────────────────────────────────────────────────────┘

| Nama          | Input Produksi Telur Harian                  |
|---------------|-----------------------------------------------|
| Actor         | Pekerja Kandang                             |
| Tujuan        | Mencatat hasil produksi telur harian        |
| Kondisi Awal  | Pekerja sudah login, di halaman input       |
| Kondisi Akhir | Data produksi tersimpan, stok bertambah     |

SKENARIO UTAMA (Basic Flow)

| # | Actor                              | Sistem                                    |
|---|------------------------------------|-------------------------------------------|
| 1 | Pekerja klik menu                  | Sistem tampilkan form input produksi      |
|   | "Input Produksi Telur"             |                                           |
| 2 |                                    | Sistem pre-fill kandang_id pekerja        |
|   |                                    | (READ-ONLY, tidak bisa diubah)            |
| 3 | Pekerja pilih tanggal produksi     | Sistem terima input tanggal               |
| 4 | Pekerja pilih satuan               | Sistem terima pilihan: Butir / Kg         |
|   | (Butir atau Kg)                    |                                           |
| 5 | Pekerja input jumlah produksi      | Sistem terima input angka                 |
| 6 | Pekerja input keterangan           | Sistem terima input keterangan (optional) |
|   | (opsional)                         |                                           |
| 7 | Pekerja klik "Simpan"              | Sistem validasi input:                    |
|   |                                    | • Tanggal ≤ hari ini?                     |
|   |                                    | • Jumlah > 0?                             |
|   |                                    | • Kandang valid?                          |
| 8 |                                    | IF valid → lanjut step 9                  |
|   |                                    | IF tidak → tampilkan error message        |
| 9 |                                    | Sistem konversi satuan otomatis:          |
|   |                                    | Jika satuan = butir:                      |
|   |                                    |   jumlah_butir = input                    |
|   |                                    |   jumlah_kg = input / 16                  |
|   |                                    | Jika satuan = kg:                         |
|   |                                    |   jumlah_kg = input                       |
|   |                                    |   jumlah_butir = input * 16               |
| 10|                                    | Sistem simpan data ke tabel produksi_telur|
| 11|                                    | Sistem update stok_telur:                 |
|   |                                    | stok_butir += jumlah_butir                |
|   |                                    | stok_kg = stok_butir / 16                 |
| 12|                                    | Sistem commit transaction                 |
| 13|                                    | Sistem tampilkan pesan sukses             |
| 14|                                    | Sistem redirect ke halaman riwayat        |

SKENARIO ALTERNATIF (Error Cases)

A1. Input Jumlah Negatif atau Nol
    • Step 7: Validasi gagal
    • Tampilkan error: "Jumlah harus lebih dari 0"
    • Pekerja perbaiki input dan retry

A2. Tanggal Lebih Besar dari Hari Ini
    • Step 7: Validasi gagal
    • Tampilkan error: "Tanggal tidak boleh melebihi hari ini"
    • Pekerja pilih ulang tanggal yang valid

A3. Pekerja Mencoba Ubah Kandang
    • Kandang field sudah READ-ONLY (disabled)
    • Sistem tidak terima perubahan kandang_id
    • Hanya kandang pekerja sendiri yang bisa input

    • Grafik menampilkan placeholder text

A2. Pekerja Kandang - Dashboard Terbatas
    • Hanya lihat: Stok, Produksi hari ini, Dashboard umum
    • TIDAK bisa: Lihat penjualan, analytics detail

A3. Pemilik Peternakan - Dashboard Lengkap
    • Lihat semua metric (stok, produksi semua kandang, penjualan)
    • Quick links ke: Laporan, Settings, etc

SKENARIO ALTERNATIF (Filter & Action)

A1. Pekerja Kandang - View Own Data Only
    • Hanya melihat riwayat produksi kandang mereka
    • TIDAK bisa lihat kandang lain
    • TIDAK ada tombol Edit/Delete

A2. Pemilik Peternakan - Full Access
    • Bisa filter by kandang (dropdown)
    • Bisa filter by tanggal (date range)
    • Bisa lihat riwayat semua kandang

    • Klik tombol "Edit" pada row
    • Buka form dengan data terpopulasi
    • Ubah qty, satuan, tanggal jika perlu

    • Sistem hitung delta stok & update

A4. Delete Data - Pemilik Only
    • Klik tombol "Delete" pada row
    • Confirm dialog: "Apakah Anda yakin?"
    • Sistem kurangi stok (reverse)
    • Sistem delete record produksi_telur
    • Reload tabel

================================================================================

┌─────────────────────────────────────────────────────────┐
│          Skenario Lihat Stok Telur                      │
└─────────────────────────────────────────────────────────┘

| Nama          | Lihat Stok Telur                           |
|---------------|-----------------------------------------------|
| Actor         | Pekerja Kandang / Pemilik Peternakan       |
| Tujuan        | Mengetahui jumlah stok telur saat ini      |
| Kondisi Awal  | User sudah login                            |
| Kondisi Akhir | Sistem tampilkan info stok (butir & kg)    |

SKENARIO UTAMA (Basic Flow)

| # | Actor                              | Sistem                                |
|---|------------------------------------|-----------------------------------------|
| 1 | User klik menu "Lihat Stok Telur"  | Sistem query tabel stok_telur          |
| 2 |                                    | SELECT * FROM stok_telur LIMIT 1       |
| 3 |                                    | Sistem tampilkan panel stok:            |
|   |                                    | • Stok Butir: X butir                   |
|   |                                    | • Stok Kilogram: Y kg                   |
| 4 |                                    | Sistem tampilkan last updated timestamp |
| 5 |                                    | Sistem check status stok:               |
|   |                                    | IF stok_butir > 200: "AMAN"             |
|   |                                    | IF stok_butir 0-200: "MENIPIS" (warning)|
|   |                                    | IF stok_butir = 0: "HABIS" (alert)      |
| 6 | User melihat info stok              | System siap untuk transaksi             |

SKENARIO ALTERNATIF (Alert Logic)

A1. Stok Menipis (kurang dari 200 butir)
    • Sistem tampilkan warning (YELLOW)
    • Pesan: "Stok menipis, pertimbangkan input produksi"
    • Optional: Suggestion ke menu Input Produksi

A2. Stok Habis (0 butir)
    • Sistem tampilkan alert (RED)
    • Pesan: "STOK HABIS! Segera input produksi baru"
    • Disable penjualan (jika diperlukan)

A3. Riwayat Stok - Pemilik Only (Optional)
    • Pemilik bisa lihat histori perubahan stok
    • Tabel: Tanggal, Jenis, Qty, Saldo, Keterangan
    • 10 perubahan terakhir

SKENARIO 8: INPUT PENJUALAN TELUR
================================================================================

┌─────────────────────────────────────────────────────────┐
│        Skenario Input Penjualan Telur                  │
└─────────────────────────────────────────────────────────┘

| Nama          | Input Penjualan Telur                     |
|---------------|-----------------------------------------------|
| Actor         | Pemilik Peternakan                         |
| Tujuan        | Mencatat transaksi penjualan (multi items) |
| Kondisi Awal  | Pemilik login, buka halaman input penjualan|
| Kondisi Akhir | Transaksi tersimpan, stok berkurang        |

SKENARIO UTAMA (Basic Flow)

| # | Actor                              | Sistem                                |
|---|------------------------------------|-----------------------------------------|
| 1 | Pemilik klik "Input Penjualan"     | Sistem tampilkan form penjualan       |
| 2 | Pemilik input tanggal jual         | Sistem terima input, validasi ≤ hari |
| 3 | Pemilik input nama pembeli         | Sistem terima input                   |
| 4 | Pemilik klik "[+ TAMBAH ITEM]"     | Sistem tampilkan row item kosong      |
| 5 | Pemilik pilih jenis/harga telur    | Sistem popup dropdown harga terbaru   |
|   |                                    | (bisa ubah manual jika perlu)         |
| 6 | Pemilik pilih satuan (butir/kg)    | Sistem terima pilihan satuan          |
| 7 | Pemilik input jumlah               | Sistem terima input angka             |
|   |                                    | Validasi vs stok tersedia             |
| 8 |                                    | Sistem auto-konversi satuan           |
|   |                                    | Sistem auto-hitung subtotal           |
| 9 | Pemilik klik "[+ TAMBAH ITEM]"     | Sistem tambah row item baru           |
|   | (jika ada lebih dari 1 item)       | (repeat step 5-8 untuk item berikutnya|
| 10| Pemilik review total harga         | Sistem tampilkan total penjualan      |
| 11| Pemilik klik "[PROSES PENJUALAN]"  | START TRANSACTION di server:          |
|   |                                    |                                       |
|   |                                    | VALIDASI HEADER:                      |
|   |                                    | • Tanggal ≤ hari ini?                 |
|   |                                    | • Min 1 item?                         |
|   |                                    |                                       |
|   |                                    | VALIDASI PER-ITEM:                    |
|   |                                    | LOOP setiap item:                     |
|   |                                    | • Harga valid?                        |
|   |                                    | • Jumlah > 0?                         |
|   |                                    | • Satuan valid?                       |
|   |                                    |                                       |
| 12|                                    | KONVERSI SATUAN PER-ITEM:             |
|   |                                    | LOOP setiap item:                     |
|   |                                    | IF satuan = 'kg':                     |
|   |                                    |   qty_butir = qty_input * 16          |
|   |                                    |   qty_kg = qty_input                  |
|   |                                    | ELSE (butir):                         |
|   |                                    |   qty_butir = qty_input               |
|   |                                    |   qty_kg = qty_input / 16             |
|   |                                    |                                       |
| 13|                                    | CEK STOK TOTAL:                       |
|   |                                    | total_butir = SUM(qty_butir per item) |
|   |                                    | IF total_butir > stok_saat_ini:       |
|   |                                    |   ERROR: "Stok tidak cukup!"          |
|   |                                    |   ROLLBACK transaction                |
|   |                                    | ELSE → lanjut step 14                 |
|   |                                    |                                       |
| 14|                                    | HITUNG TOTAL HARGA:                   |
|   |                                    | total = 0                             |
|   |                                    | LOOP setiap item:                     |
|   |                                    |   subtotal = qty * harga_satuan       |
|   |                                    |   total += subtotal                   |
|   |                                    |                                       |
| 15|                                    | INSERT PENJUALAN:                     |
|   |                                    | INSERT INTO penjualan                 |
|   |                                    | (user_id, tanggal_jual, nama_pembeli, |
|   |                                    |  total_harga, keterangan)             |
|   |                                    | → Get $penjualan_id                   |
|   |                                    |                                       |
| 16|                                    | INSERT DETAIL PENJUALAN:              |
|   |                                    | LOOP setiap item:                     |
|   |                                    | INSERT INTO detail_penjualan          |
|   |                                    | (penjualan_id, harga_telur_id,        |
|   |                                    |  satuan_jual, jumlah_jual, jumlah_butir|
|   |                                    |  jumlah_kg, harga_satuan, subtotal)   |
|   |                                    |                                       |
| 17|                                    | UPDATE STOK:                          |
|   |                                    | UPDATE stok_telur                     |
|   |                                    | SET stok_butir -= total_butir_diambil |
|   |                                    | stok_kg = stok_butir / 16             |
|   |                                    | updated_at = NOW()                    |
|   |                                    |                                       |
| 18|                                    | COMMIT TRANSACTION                    |
|   |                                    |                                       |
| 19|                                    | Success message:                      |
|   |                                    | "Penjualan berhasil! Ref: #PJL-001"   |
| 20|                                    | Redirect ke laporan/riwayat penjualan |

SKENARIO ALTERNATIF (Error Cases)

A1. Stok Tidak Cukup
    • Step 13: Validasi gagal
    • ROLLBACK semua transaksi
    • Error: "Stok tidak cukup untuk item [nama item]"
    • Pemilik kurangi qty atau hapus item

A2. Harga Tidak Ditemukan
    • Step 5: Dropdown harga kosong (belum input harga)
    • Error: "Harga telur belum di-input hari ini"
    • Pemilik harus input harga dulu di menu Master Harga

A3. Jumlah Negatif
    • Step 7: Validasi gagal
